# Функциональные возможности Pomen

## Обзор

Pomen — плагин Intermasq, предназначенный для назначения доменных имён
контейнерам Podman, запускаемым через Quadlet внутри виртуальных машин.
Применяется принцип **выборочного опроса по запросу**: фоновое обращение к
сети отсутствует, все действия инициируются администратором.

---

## Управление реестром виртуальных машин

- **Управление через веб-интерфейс.** Добавление, удаление и просмотр
  виртуальных машин с Podman выполняются непосредственно в веб-интерфейсе;
  редактирование файлов на сервере не требуется.
- **Динамический реестр.** Сведения о виртуальных машинах хранятся в `vms.json`
  отдельно от статического `config.json`, что упрощает добавление и удаление
  короткоживущих машин.
- **Уникальность имён.** Добавление виртуальной машины с уже существующим
  именем приводит к обновлению её параметров (IP-адрес, вебхук, секрет), а не
  к созданию повторной записи.
- **Изоляция по узлам.** Каждая виртуальная машина связана с узлом, описанным
  в `config.json`; это определяет экземпляр Caddy, в который помещаются
  маршруты.
- **Безопасное удаление.** При удалении виртуальной машины из реестра её
  маршруты в Caddy и записи в `routes.json` сохраняются (отмечаются как
  неактивные); очистка выполняется только вручную на вкладке «Маршруты». Это
  предотвращает случайную потерю назначенных доменов при пересоздании машины.

## Обнаружение контейнеров (по запросу)

- **Кнопка «Обновить».** Плагин направляет запрос к вебхуку виртуальной машины
  (`POST /hooks/podman` с заголовком `X-VM-Secret`); вебхук выполняет
  `podman ps --format json` и возвращает результат в формате JSON.
- **Отсутствие фонового опроса.** Между запросами администратора сетевой
  трафик не генерируется; SSH-сессии и хранение ключей на сервере плагина не
  требуются.
- **Разбор фактического вывода Podman:**
  - Имя — из `Names[0]` с удалением префикса `systemd-` и нумерации
    (`systemd-01-athens` → `athens`).
  - Порт — из `Ports[0].host_port` (надёжнее ручных меток).
  - Состояние — из полей `State`/`Status`: работающие контейнеры отмечаются
    зелёным, остановленные — серым.
- **Приоритет меток.** При наличии в файле `.container` меток `Label=name-…`,
  `Label=port-…`, `Label=proto-…` их значения имеют приоритет над
  автоматически определёнными.

## Назначение доменов (Provision)

- **Схема FQDN:** `<container>.<vm>.<node>.internal`
  (например `athens.obshaga.yadr00.internal`). Имя узла всегда включается в
  домен, что исключает неоднозначность при большом числе виртуальных машин.
- **Caddy reverse_proxy.** Маршрут помещается в Admin API Caddy
  соответствующего узла
  (`POST /config/apps/http/servers/srv0/routes`).
- **TLS через Step-CA.** Автоматически создаётся политика TLS с ACME-запросом
  к внутреннему центру сертификации Step-CA; самоподписанные сертификаты
  отключены глобально.
- **Идемпотентное обновление (upsert).** Повторный вызов Provision для того же
  контейнера не приводит к дублированию политики TLS: применяется метод
  `upsertByID` (PUT для существующих объектов, POST для новых). Это устраняет
  ошибку Caddy `cannot apply more than one automation policy to host`.
- **Принудительный перезапуск Caddy.** После применения маршрута плагин
  направляет `POST /stop` в Caddy; системный юнит с параметром `Restart=always`
  перезапускает процесс, после чего Caddy перечитывает `autosave.json` и
  применяет вновь выпущенный сертификат, минуя устаревший кэш.
- **Идемпотентные идентификаторы.** Маршрут — `pod-<vm>-<name>-<node>`,
  политика TLS — `podtls-<vm>-<name>-<node>`. За счёт префикса `pod-`
  гарантируется отсутствие конфликтов с записями `proxy-<VMID>-…` плагина
  Povez при общем экземпляре Caddy.

## Маршруты и состояние

- **Таблица маршрутов.** Все назначенные домены представлены единым списком
  на вкладке «Маршруты»: домен, виртуальная машина, IP, порт, протокол, узел,
  время последнего обновления.
- **Сохранение неактивных записей.** При остановке контейнера или недоступности
  виртуальной машины запись в таблице сохраняется; автоматическая очистка не
  выполняется.
- **Ручная очистка.** Кнопка удаления напротив записи удаляет маршрут и
  политику TLS из Caddy, а также запись из `routes.json`. Проверка состояния
  контейнера не выполняется — решение об удалении принимает администратор.
- **Восстановление конфигурации Caddy (Replay).** Кнопка «Replay»
  перезаписывает конфигурацию Caddy на основании файла `routes.json` методом
  upsert, после чего выполняется один запрос `POST /stop` на каждый
  затронутый узел. Применяется после сброса Caddy или при миграции.

## Безопасность

- **Непривилегированное выполнение.** Плагин работает как дочерний процесс
  `intermasq.service` от имени непривилегированного пользователя `intermasq`;
  права ограничены собственным каталогом и сокетом.
- **Unix-сокет.** Связь с Intermasq осуществляется через
  `/run/intermasq/sockets/pomen.sock` (права `0770`); открытых TCP-портов
  плагина в рабочем режиме нет.
- **Секрет для каждой виртуальной машины.** Каждый вебхук защищён собственным
  секретом, передаваемым в заголовке `X-VM-Secret`. Секреты хранятся только в
  `vms.json` с правами `0660` для владельца `intermasq`.
- **Отсутствие SSH-ключей.** Плагин не обращается к виртуальным машинам по SSH;
  все запросы представляют собой исходящий HTTP-трафик от плагина к вебхуку,
  поэтому утечка SSH-ключей исключена.
- **Проверка секрета на стороне вебхука.** Вебхук (adnanh/webhook) проверяет
  заголовок `X-VM-Secret` до выполнения команды; неавторизованные запросы до
  `podman` не доходят.

## Пользовательский интерфейс

- **Единый исполняемый файл.** Бэкенд на Go и фронтенд на Vue 3 (один файл
  `index.html`) объединены в один файл размером около 10 МБ; Python, PHP или
  отдельный веб-сервер не требуются.
- **Три вкладки интерфейса:** «Виртуальные машины» (управление реестром),
  «Контейнеры» (обнаружение и назначение доменов), «Маршруты» (просмотр
  состояния, очистка и восстановление).
- **Тёмная тема.** Bootstrap 5 с параметром `data-bs-theme="dark"`.
- **Отображение состояния контейнеров.** Индикаторы работающих и остановленных
  контейнеров формируются на основании поля `State` вывода `podman ps`.
- **Защита от ошибок.** Кнопка «Выдать домен» недоступна, если у контейнера не
  определён порт; назначение домена без порта восходящего потока невозможно.

## Интеграция с инфраструктурой

- **DNS-зона Intermasq не модифицируется.** Отдельные DNS-записи для
  контейнеров не создаются; в dnsmasq достаточно одной wildcard-записи
  `address=/.node.internal/CADDY_IP` — маршрутизация по заголовку Host
  выполняется Caddy.
- **Сосуществование с Povez.** Оба плагина помещают маршруты в общий экземпляр
  Caddy с различными префиксами `@id` (`pod-` и `proxy-` соответственно), что
  исключает взаимное затирание маршрутов.
- **Совместимость с GitOps.** Метки в файлах `.container` управляются через
  репозиторий (Quadlet); плагин файлы на виртуальной машине не изменяет.
- **Шаблон развёртывания вебхука.** Файл `pomen-hooks.json` разворачивается
  средствами CI аналогично `hooks.json` (envsubst и SCP) без ручного
  вмешательства на виртуальной машине.
